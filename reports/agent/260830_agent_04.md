## 2. v1 架构

最终执行链为：

```plain
User scientific request
  → minimal Figure Intent
  → Template Knowledge route（仅在选择不明确时）
  → compact Template Registry
  → selected family contract
  → canonical builder
  → deterministic style/layout/rendering runtime
  → runtime anatomy/PDF validator
  → publication-size PDF + PNG preview
```

LLM 只负责 scientific intent、data role mapping、template、geometry preset、typography mode 与不能安全推断的科学语义。物理尺寸、字体、颜色、stroke、marker、tick、legend、panel、colorbar、margin 和 PDF 输出均由运行时决定，不进入 Figure Intent。

模板层按科研语法组织为 13 个 public family：

```plain
src/axiomfig/templates/
├── index.yaml
├── registry.py
├── line/
├── scatter/
├── bar/
├── distribution/
├── heatmap/
├── estimation/
├── diagnostics/
├── ordination/
├── association/
├── flow/
├── field/
├── omics/
├── survival/
└── layouts/
```

每个 family 保持普通 `builders.py`、显式 `BUILDERS` mapping 与小型 `contract.yaml`。`layouts/` 有 4 个注册能力，但不是科研图 family，也不进入 public Gallery。项目没有引入 plugin framework、metaclass、DSL、database、动态 import magic 或大型 schema framework。

## 3. 架构迁移与 Rougier 原则

项目从 Round 05 的确定性 visual kernel 与 Round 06 的 33-template 基础继续收敛，删除了旧式粗粒度、平铺与重复清单思路。现在 `index.yaml` 是模板发现的唯一源；registry、contract、显式 builder 与 Gallery validator 必须完全一致，Gallery 不再维护第二份手写模板列表。

本轮核验了 Nicolas P. Rougier 的 *Scientific Visualization: Python + Matplotlib* 上游及用户 fork，记录的共同源提交为 `62fa569f30333c817c13e4dc757877c1192fd15a`。AxiomFig 只提炼实现后果，没有复制书中正文、图片或源码：

1. Figure、Axes、Artist 与 ornament ownership 必须显式；
2. 出版物理尺寸和 point 单位优先于像素试调；
3. layout 是约束系统，Primary/Auxiliary Axes 必须被 panel footprint 所有；
4. typography 是统一栈，颜色由数据语义选择；
5. ornament 只服务科学信息，必须经过碰撞与边界检查；
6. vector-first 输出，禁止误导性编码、rainbow quantitative map 与无意义 chartjunk。

这些约束已进入 `references/scientific-visualization-principles.md`、style/layout/validation contract 与运行时代码。

## 4. 期刊图型调查

`references/journal-plot-taxonomy.md` 记录了 25 篇 2024–2025 年公开论文的 caption-level census：Nature、Nature Communications、Science Advances、Environmental Science & Technology、Water Research 各 5 篇。该调查只记录图形语法，不复制图片，也不把 caption 无法支持的判断写成事实。

近似 paper-level lower bound 为：line/time-series 15/25、image/schematic 15/25、scatter/regression 13/25、distribution 12/25、ordination 7/25、heatmap/matrix 6/25、omics 6/25、bar/dot 3/25、association/network 3/25、estimation 2/25、survival 2/25、field/map 1/25。结果支持当前 13-family 范围；microscopy、chemical structure、GIS、general diagram、animation、dashboard 与大型 3D suite 不属于 v1。

## 6. Mantel、颜色与 panel label

`association/mantel` 是 first-class template，使用相关矩阵、稀疏 Mantel links、关系强度编码、显著性编码和紧凑 legend。它只负责预计算结果的科学可视化，不计算 Mantel test，也不依赖大型 network plotting package。Sans 与 serif PDF/PNG 均由正式 registry 路径生成并通过 validator。

颜色的唯一源仍是 `styles/colors.yaml`。Qualitative 使用 canonical category palette，sequential 使用 `cividis`，diverging 使用 `RdBu_r`，cyclic 使用 `twilight`；signed matrix/field 必须给出有意义的 center，不能与正值 concentration field 混用语义。

Panel label 保留 Round 06 已修正语义：旧锚点为 Outer Panel Footprint 左上角，视觉距离主要来自 footprint 到 Primary Axes frame 的 inset，而非单独的 2 pt translation。新锚点是 Primary Axes frame 左上角，同时 footprint 预留 label gutter；中央物理 token 为 `-1 pt/+1 pt`，是旧 `-2 pt/+2 pt` 的 0.5 倍。2×2、2×3、3×2 在 sans/serif 下均保持相同 frame gap、等尺寸 panel、无 y-label/legend 碰撞，colorbar 作为 Auxiliary Axes 留在所属 footprint 内。

## 7. Figure Intent 与 Agent 协议

`src/axiomfig/intent.py` 实现了冻结的最小 Figure Intent，支持 YAML/JSON intent、CSV/JSON data 与普通显式验证。禁止字段包括 `font_size`、`linewidth`、`tick_length`、`legend_x`、`panel_offset`、`bar_width`、`colorbar_width` 和 `subplot_wspace`。必须显式提供的 uncertainty type、diverging center、significance、censoring 或 adjusted-p semantics 不会被运行时猜测。

当前有 12 个 external-data adapter：`line/single`；`scatter/simple`、`scatter/grouped`、`scatter/parity`；`bar/vertical`；`distribution/violin`；`heatmap/correlation`；`estimation/forest`；`diagnostics/residual`；`ordination/pca_scores`；`omics/volcano`；`survival/kaplan_meier`。全部 55 个模板均支持无数据 canonical example；其他 data-bearing intent 会明确失败，不会静默忽略数据。

用户入口为：

```plain
axiomfig-intent
axiomfig-render
axiomfig-validate
axiomfig-gallery
```

`SKILL.md` 已压缩为 routing document。正常 Agent 路径只读 Skill、90 行 registry 与一个 family contract；选择不明确时，再读 15 行 Knowledge index 和一个被路由的 topic。Builder source、全部 contract 和全部 Knowledge topic 均不是正常 prompt context。

## 8. Template Registry、Knowledge Base 与 token cost

`src/axiomfig/templates/index.yaml` 只有 family、variant、geometry 和 public/layout 分类：90 行、2,895 bytes，按 `ceil(bytes/4)` 约为 724 tokens。它不包含模板推荐长文。

`references/template-knowledge/` 由一个 15 行 `index.yaml` 和 5 个短 topic 组成，按 trend/comparison、distribution/relationship、matrix/multivariate、uncertainty/model、domain-specialized progressive disclosure。它回答“哪种 intent 适合哪个 template”；registry/contract 只回答“模板存在什么能力”，二者没有混合。

Evaluation 的代表性 prompt-side 测量为：

| 输入 | Bytes |
|---|---:|
| `SKILL.md` | 3,858 |
| Template Registry | 2,895 |
| selected scatter contract | 509 |
| representative Figure Intent | 75（Evaluation fixture） |
| 合计估算 | 约 1,835 tokens（bytes/4） |

仓库中的可复制 `examples/parity-intent.yaml` 因完整角色名为 116 bytes；Evaluation 指标使用其最小代表 fixture。该差异不影响 progressive-disclosure 结论。

唯一一次完整视觉审查覆盖核心与 advanced family、Mantel、sans/serif 一致性以及 2×2、2×3、3×2 layout。检查了 line/fill stroke、ticks、categorical axis、scatter alpha/size、bar labels、panel labels、legend、subplot symmetry、heatmap colorbar、font 与 PDF 边界；没有发现需要 repair pass 的 Important 问题。

## 10. Validation 与 Evaluation

Runtime validation 在渲染前后检查：Artist anatomy/ownership、panel 尺寸、Primary/Auxiliary containment、legend/panel-label/annotation collision、overflow/clipping、PDF physical geometry、font stack、embedded subset font、Type 3 font、文本页面边界和文件有效性。任何 gate 失败都会停止，不把问题 PDF 当作成功输出。

`evaluation/cases.yaml` 包含 24 个确定性请求，覆盖 14 个 intent category：trend、comparison、distribution、relationship、uncertainty、matrix、model evaluation、ordination、association、flow、field、omics、survival 和 composition。实测结果为 24/24 routing/intent PASS、24/24 render PASS、repeatability PASS、mixed-panel PASS，case pass rate 与 render success rate 均为 100%。没有使用 LLM judge 代替可确定检查。

## 11. Packaging、安装与 CI

`pyproject.toml` 已冻结为 `1.0.0`，要求 Python 3.11+，提供 MIT metadata、4 个 CLI entry point、dev extra 与完整 package data。Wheel 包含 styles、contracts、fonts、font license attribution、LaTeX resources、Knowledge Base 和 Evaluation corpus，安装后不依赖 repository root。

隔离 wheel 测试在临时 venv 中构建并安装 wheel，随后调用 installed CLI 与 package resources，结果通过。没有创建新的 conda environment。

GitHub Actions 采用 least-privilege permissions、SHA-pinned official actions，并在 Python 3.11/3.12 上执行 install、Ruff、Skill validation、fast deterministic tests、routing Evaluation 和 headless render。候选 SHA `e3360dfaac5c8698b83842e2049ae3182bb5cb21` 的 run `33270422541` 两个 job 均通过，四个 check 均为 success、annotations 为 0。`actions/checkout` 已更新到经远端 tag 核验的 v5.0.1 SHA，消除了旧 Node 运行时弃用告警。

## 14. Typography 状态

Sans 为 bundled Latin Modern Sans，serif 为 bundled XCharter/XCharter Math，mono 为 bundled Maple Mono；字体文件与 redistribution attribution 均进入 wheel。Arial、Times New Roman、SimSun、Yu Gothic 仅为 `bundled: false` optional system metadata，商业字体未复制入仓库。
