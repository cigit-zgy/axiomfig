# AxiomFig

## Core contract

AxiomFig is deterministic-first. Read the three canonical sources before changing a visual default:

- `styles/style.yaml`: geometry, sizes, strokes, ticks, axes, legends, panels, plot defaults, and rendering;
- `styles/fonts.yaml`: sans/serif/mono/math families, exact files, provenance, license attribution, and optional system fonts;
- `styles/colors.yaml`: canonical scientific palettes.

Do not introduce `.mplstyle` files or one-off `rcParams` overrides. Python is a thin YAML-to-`rcParams`/token consumer; template builders own data and scientific meaning, not visual defaults.

## Workflow

1. Read `src/axiomfig/templates/index.yaml` and select one public `<family>/<variant>` ID. Then read only that family's `contract.yaml`; see [references/template-contract.md](references/template-contract.md) and [references/template-taxonomy.md](references/template-taxonomy.md).
2. Choose geometry `single-column` (90 mm), `onehalf-column` (140 mm), or `double-column` (190 mm). Font sizes remain physical points and never scale with width.
3. Choose a complete Latin/math typography mode: `sans` (default) or `serif`. Run `python scripts/check_fonts.py`; read [references/typography.md](references/typography.md) before changing font metadata.
4. Declare scientific intent and ornament needs; let the deterministic runtime derive positions and dimensions. Read [references/style-contract.md](references/style-contract.md), [references/layout-contract.md](references/layout-contract.md), and [references/validation-contract.md](references/validation-contract.md).
5. Render with `python scripts/render.py <template> --output <stem> [--geometry ...] [--typography sans|serif]`. The formal PDF passes through Tectonic; the PNG is rasterized from that PDF.
6. Validate with `python scripts/validate.py <output-directory>` and inspect the rendered page. For a repository change, rebuild the registry projection under `gallery/sans/`, `gallery/serif/`, and `gallery/technical/latex/`, then inspect all 68 PDF/PNG pairs.

## Non-negotiable visual behavior

- Any visual property that can be derived deterministically MUST NOT be generated by the LLM. The Agent may select scientific intent, an existing template, data mapping, typography mode, geometry preset, palette, and a small number of scientific semantic parameters. It must not emit figure size, panel footprint, subplot spacing, panel-label coordinates, legend coordinates/row count/spacing, colorbar position/size, bar width, tick geometry, margins, font sizes, line widths, or palette values.
- Never set an artist-wide alpha on filled geometry. Put configured alpha in face RGBA and keep the black edge RGBA fully opaque at `fill_edge`.
- Never invent template-local alpha, marker size, bar width, stroke width, tick length, legend gap, or panel-label coordinates. Change the owning YAML token and its shared helper when the contract itself changes.
- Use `bar_width(1)` for ordinary bars and `bar_width(series_count)` for grouped bars. Category count does not alter width.
- Use `series_style(index)` for multi-series identity. The ordered line cycle begins solid, dash-dot, dotted, long-dash and is redundantly paired with color and marker. Use `reference_line_kwargs()` for secondary/reference lines; its default is dash-dot.
- Treat an Outer Panel Footprint as the top-level GridSpec slot and register its Primary Axes, Auxiliary Axes, and panel-owned artists before ornament finalization. A colorbar is Auxiliary Axes contained inside the same footprint; it cannot expand the footprint or compress a peer. Reserve the label gutter inside the footprint, but anchor 11 pt bold labels to the Primary Axes frame upper-left with the single physical-point translation.
- Treat legends as Figure-level Ornaments. Fit a multi-series legend with `N`, `N-1`, … columns and accept the first candidate inside the figure boundary without axes or panel-label collision. Do not reduce columns merely because it is wider than the data axis.
- Run the figure-anatomy validator for registered layouts. Containment, alignment, collision, and overflow failures are runtime errors, not optional visual-review notes.

## Scientific LaTeX boundary

Use only the verified general scientific syntax recorded in [references/latex-contract.md](references/latex-contract.md). Do not invent unit, chemistry, math, or color macros. `gallery/technical/latex/` is genuinely Tectonic-native. The Matplotlib Gallery embeds text before a separate Tectonic wrapper; TeX-native macro expansion inside Matplotlib labels remains **DEFERRED** and must not be claimed.

## Preference changes

Update the owning YAML token, the thin consumer/helper, the relevant reference contract, and a behavioral test. Use only `normal`, `boundary`, and `overflow/error` cases; never launch combinatorial visual searches.

## Completion

Complete only when deterministic tests pass, each Matplotlib typography mode contains all 33 public registry PDF/PNG pairs, `gallery/technical/latex/` contains both Tectonic-native pairs, no Gallery orphan exists, PDFs have the intended geometry and embedded/subset non-Type-3 fonts, and visual inspection finds no translucent edges, clipping, overlap, asymmetric outer panels, malformed legends, or missing glyphs.
