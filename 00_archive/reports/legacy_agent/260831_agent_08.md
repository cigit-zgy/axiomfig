# AxiomFig Scientific Figure Element Contracts and A/B Benchmark

## 结论

本轮完成了 Scientific Figure Element Contract knowledge layer，并用冻结的 product baseline 与
冻结的 treatment 做了 `32 × 2 × 3 = 192` 个隔离 Agent 会话。结论为：

- **LLM decision complexity: REDUCED**；semantic-core accuracy 从 `38.37%` 提升到
  `89.36%`，invalid public-surface claim 从 `4.65%` 降到 `1.06%`；
- **LLM retrieval complexity: REDUCED**；median reads 从 `3` 降到 `2`，全部 78 个
  treatment exception sessions 都只读取 `index + one topic`；
- **LLM token cost: REDUCED**；可获得的真实 Codex total-token median 从 `24,253` 降到
  `13,142`（`-45.81%`）；
- **Overall architecture value: POSITIVE**。

该结论不来自文档质量或 pytest。它来自同模型、同配置、同 gold、同 32 cases、每侧三次新鲜会话的
实际 A/B 结果。adversarial low-level 组仍然较弱，因此建议 KEEP knowledge layer、OPTIMIZE
低层措辞到语义目标的判定，不实施新的 numeric/backend surface。

## Element-contract architecture

The permanent knowledge layer is:

```text
references/element-contracts/
├── index.md
├── axes.md
├── marks.md
├── ornaments.md
└── annotations.md
```

Each topic maps qualitative default -> legitimate exception -> exact current surface/status ->
runtime ownership/relations/validation. Stable physical values remain only in packaged YAML and
runtime code. The documents use the ontology from `figure-anatomy.md` and cross-link, rather than
copy, style/layout/typography contracts.

No production runtime, Figure Intent schema, family contract, template registry, dependency, or
Gallery semantics changed.

## Progressive-disclosure routing

`SKILL.md` gained one four-line exception route. Default requests stop before the element index.
Non-default requests read the index and at most one element topic when possible. The treatment
observed exactly this behavior:

- default sessions reading an element file: `0/18`;
- exception sessions: `78/78` read index + exactly one element topic;
- exception sessions reading more than one element topic: `0/78`;
- treatment reads of broad `style-contract.md` or `layout-contract.md`: `0`;
- baseline broad reads: style `40`, layout `29`, figure-intent `38`, registry `52`.

`SKILL.md` grew from `3,277` to `3,646` bytes. The release evaluator's normal discovery estimate is
`1,814` tokens after treatment; the same byte/4 calculation on the baseline normal surface is
approximately `1,721`, an increase of about `93` tokens. Despite this static increase, measured
default-session median total tokens fell from `12,693` to `3,749.5` because the exception gate made
the stop condition explicit.

## A/B benchmark design

- Corpus: 32 frozen cases (`A=6`, `B=8`, `C=8`, `D=6`, `E=4`).
- Repetitions: 3 fresh logical sessions per case per condition.
- Total: 192 logical sessions; 669 fresh Codex processes/turns, 669 unique session IDs.
- Model/config: `gpt-5.6-sol`, reasoning `high`, Codex CLI `0.149.1`, same both sides.
- Baseline: detached worktree at `b55f1ab`; treatment: detached worktree at `dc71bda`.
- Agent initially saw only `SKILL.md`; all later reads were broker allowlisted, one file/turn.
- Agent tools, shell, apps, browser/web search, skill search, and multi-agent were disabled;
  filesystem was read-only. Provider transport was necessarily available, but no Agent-facing
  network/repository tool existed.
- Gold/scorer/tests/reports/`.git`/other-condition outputs were absent from both sandboxes.
- Treatment documentation was frozen before either condition ran and never tuned afterward.

## LLM decision complexity

`element` and `recommended_surface` are free text, so the scorer reports both strict all-field exact
match and a semantic core consisting of non-default decision, topic, status, implementation level,
default preservation, and scientific-anchor preservation. Exact phrase mismatch is not silently
converted into correctness.

| Metric | Baseline | Treatment | Delta | Interpretation |
|---|---:|---:|---:|---|
| Parse success | 89.58% | 97.92% | +8.34 pp | fewer format failures |
| Semantic-core accuracy, parsed | 38.37% | 89.36% | +50.99 pp | strongly reduced |
| Semantic-core accuracy, all 96 | 34.38% | 87.50% | +53.12 pp | failures counted wrong |
| Topic accuracy | 90.70% | 98.94% | +8.24 pp | focused routing |
| Surface-status accuracy | 45.35% | 95.74% | +50.39 pp | public boundary clarified |
| Implementation-level accuracy | 65.12% | 95.74% | +30.62 pp | public/runtime/none clarified |
| Exact surface-name accuracy | 1.16% | 57.45% | +56.29 pp | treatment often names real field |
| Strict all-free-text-field match | 0.00% | 9.57% | +9.57 pp | phrase-sensitive diagnostic only |
| Invalid AVAILABLE claim | 4.65% | 1.06% | -3.59 pp / -77.13% | reduced |
| Low-level parameter leakage | 0.00% | 0.00% | 0 | floor / unchanged |
| Numeric visual invention | 0.00% | 0.00% | 0 | floor / unchanged |
| Backend-name leakage | 0.00% | 0.00% | 0 | floor / unchanged |
| Default unnecessary override | 0.00% | 0.00% | 0 | no regression |

All predicted AVAILABLE strings were manually reviewed. They named real current surfaces; the
invalid-rate events were misuse of a real public surface for a request whose audited adjustment was
not public, not a nonexistent field name. Therefore literal API hallucination was `0` in both
conditions, while unsafe public-surface applicability fell from four parsed decisions to one.

**Verdict: REDUCED.** The treatment improved semantic boundary accuracy materially and reduced
invalid public-surface claims by more than the task's 40% relative guidance threshold.

The prior complex-figure audit already showed real pressure around dense selected labels,

## Architecture recommendation

### KEEP

- Keep `index + one topic`; it reduced decision, retrieval, and measured token cost.
- Keep exact status vocabulary and explicit runtime ownership.
- Keep all deterministic numeric values out of Agent prose.

### OPTIMIZE

- In a future benchmark-only schema, replace free-text `element` with an enum and give
  `recommended_surface` a canonical ID plus optional prose; strict string scoring currently
  understates semantic correctness.
- Clarify the benchmark distinction between “the user asked for a non-default appearance” and “a
  scientifically justified semantic non-default exists,” especially for adversarial numeric asks.
- Preserve the current treatment docs; do not tune them against these 192 seen outputs.

### ADD LATER

Evidence supports separate future design work for:

1. collision-aware selected-label policy with bounded displacement, priority, and semantic
   connectors;
2. shared legend/Colorbar scope and side/orientation within a real user-data composition contract;
3. semantic axis-scale requests where scientific scale meaning can remain explicit.

### REJECT / DO NOT ADD

- marker `s`, tick length/width, `bbox_to_anchor`, manual Axes coordinates;
- solver force/candidate counts or backend switches;
- generic kwargs, arbitrary artist commands, or a second visual-intent schema.
