## 3. Design decisions

最终流程为：

```text
scientific intent
  -> native Matplotlib template
  -> deterministic .mplstyle composition
  -> vector intermediate PDF
  -> standalone TeX wrapper
  -> Tectonic final PDF
  -> Poppler PNG preview
  -> structural/font/text/boundary validation + visual inspection
```

关键取舍：

1. 不建立 plotting wrapper class hierarchy。模板继续使用原生 Matplotlib API；Python 层只负责 `.mplstyle` 无法可靠承担的冲突检测、精确字体发现、模板定位、外部渲染命令和产物验证。
2. 风格以七层固定顺序组合。参数所有权由 style layer 表达，模板不能重复设置字体、figure width、基础字号、axes/tick 线宽、color cycle 或导出格式。
3. PDF 和 PNG 只有一条 source path。PNG 由最终 Tectonic PDF rasterize，不再独立调用 `savefig(..., png)`，避免预览与正式 PDF 漂移。
4. gallery 只提交最终 8 个 PDF 和 8 个 PNG。TeX、日志、中间 PDF、Poppler preview 和 manifest 全部进入忽略的 `tmp/`。
5. 字体缺失为 hard failure，不使用 Matplotlib 默认字体或系统字体静默替换。

## 4. SciencePlots review

- 使用原生 `.mplstyle` 作为主要配置载体；

- 未建立大量 style alias 或便利 wrapper；这些会扩大 agent 的自由选择空间并增加未验证组合。

## 5. Style architecture

固定 composition 顺序：

```text
base -> geometry -> typography -> colors -> plot -> language -> rendering
```

层职责：

| Layer | 当前模块 | 责任 |
|---|---|---|
| base | `publication` | 8.5 pt 基准、axes/ticks、minor ticks、legend、背景和 constrained layout |
| geometry | `single-column`, `onehalf-column`, `double-column` | 90/140/190 mm 物理宽度及默认 4:3 高度 |
| typography | `sans` | Latin Modern Sans 与 Latin Modern Math 的 Matplotlib/mathtext contract |
| colors | `default`, `muted`, `colorblind` | Paul Tol bright、muted、high-contrast qualitative cycle |
| plot | `line`, `scatter`, `bar`, `distribution`, `heatmap` | 仅该图形语法拥有的 line/marker/patch/image 参数 |
| language | `multilingual` | Latin、SC、JP 有序 family contract；模板对 SC/JP 做显式映射 |
| rendering | `vector` | PDF/PS font type 42、PDF 默认输出、300 dpi preview policy |

`compose_styles()` 使用 `matplotlib.rc_params_from_file(..., fail_on_error=True)` 加载每层，并记录每个 key 的 owner。重复 key 默认抛出 `StyleConflictError`。当前唯一声明的 override 是 `typography -> language` 对 `font.family` 的覆盖，因为 language 层要把单一 Latin family 扩展为有序多语言列表。不存在 agent 任意手工 override 接口；用户偏好变化必须修改所属 style、reference 和 tests。

## 6. Template architecture

第一版 registry 含 17 个可运行 builder：

- line：single、multi-series、marker、confidence interval；
- scatter：basic、grouped、parity；
- bar：vertical、grouped；
- distribution：boxplot、violin；
- heatmap：annotated matrix；
- model evaluation：observed-predicted summary、residual；
- layout：2-panel、4-panel/shared legend；
- multilingual：Latin + SC + JP + math pipeline probe。

模板文件位于 `templates/`，每个文件可作为普通 Python 模块直接运行，并由 `src/axiomfig/templates.py` 的显式 registry 装载。模板负责数据、plot call、axis labels、units、legend 位置、annotation 和 panel arrangement；样式负责全局尺寸、字体、字号、ticks、基础线宽、palette 和导出规则。测试逐一实例化 17 个 builder，并确认它们不改变 contract `rcParams`。

## 7. Typography

正式 contract：

| Role | Display contract | Matplotlib/PDF family | macOS 测试文件 |
|---|---|---|---|
| Latin | Latin Modern Sans | `LMSans10` | `/Users/wenv/Library/Fonts/lmsans10-regular.otf`，同时检查 bold/oblique/bold-oblique |
| Math | Latin Modern Math | `Latin Modern Math` | `/Users/wenv/Library/Fonts/latinmodern-math.otf` |
| Simplified Chinese | Noto Sans CJK SC | `Noto Sans CJK SC` | `/Users/wenv/Library/Fonts/NotoSansCJK.ttc` |
| Japanese | Noto Sans CJK JP | `Noto Sans CJK JP` | `/Users/wenv/Library/Fonts/NotoSansCJK.ttc` |

字体发现策略：Latin Modern 以 Homebrew cask 的确定文件名和字体元数据双重核验，并向 Matplotlib 注册 regular/bold/oblique/bold-oblique；CJK 以 exact family 调用 `findfont(..., fallback_to_default=False)`，随后再次核对文件内 family。中文和日文文本分别调用明确的 `zh` / `ja` 映射，避免共享汉字依赖 fallback 顺序。

Fallback policy：任何文件缺失、family 不匹配或隐式 fallback 都抛出 `FontContractError`。本轮在 macOS/Apple Silicon 上实际通过 `scripts/check_fonts.py`。最终 `07_multilingual.pdf` 的 `pdffonts` 行包含 `NotoSansCJKsc-Regular`、`NotoSansCJKjp-Regular`、`LatinModernMath-Regular` 和 `LMSans10-Regular`，均为 embedded/subset，并有 Unicode mapping。

## 8. Tectonic rendering

### 8.1 失败路线

已实际实验把 `mpl.rcParams['pgf.texsystem']` 设置为 `tectonic`。Matplotlib 3.11.1 立即返回：

```text
ValueError: Key pgf.texsystem: 'tectonic' is not a valid value;
supported values are ['xelatex', 'lualatex', 'pdflatex']
```

因此没有伪装为 PGF backend 支持，也没有把 `xelatex` 字符串机械替换成 `tectonic`。

### 8.2 最终路线

1. Matplotlib 以明确字体和 `pdf.fonttype: 42` 生成矢量 `intermediate.pdf`。
2. 生成 `wrapper.tex`：

   ```tex
   \documentclass[border=0pt]{standalone}
   \usepackage{graphicx}
   \begin{document}
   \includegraphics{intermediate.pdf}
   \end{document}
   ```

3. 对每张 gallery 图实际运行同一形式的命令；以 `01_line` 为例：

   ```text
   /opt/homebrew/bin/tectonic \
     --outdir /Users/wenv/Documents/skills/axiomfig-skill/tmp/gallery/01_line \
     --keep-logs --keep-intermediates wrapper.tex
   ```

4. 将 Tectonic 生成的 `wrapper.pdf` 复制为正式 gallery PDF。
5. 运行 Poppler `pdftoppm -f 1 -singlefile -png -r 300 <final.pdf> <preview>`，从该最终 PDF 生成 PNG。

Intermediate files 均位于 `tmp/gallery/<stem>/`：`intermediate.pdf`、`wrapper.tex`、`wrapper.aux`、`wrapper.log`、`wrapper.pdf`、`preview.png`。`tmp/gallery/gallery_manifest.json` 记录每张图的 style paths、完整 Tectonic command、intermediate path、尺寸、文件大小和字体行。

可靠性边界：Tectonic 是最终 PDF container 的确定性生产者，并真实解析/包含矢量 intermediate；图中字符的字形 shaping 和 embedding 由 Matplotlib 的明确字体 contract 完成，而不是由 TeX 重新排版。最终 PDF 再以 `pdffonts` 和 `pdftotext` 复核字体与文本。

## 12. Problems found

1. Matplotlib PGF backend 不接受 `tectonic`，不能采用直接 PGF engine substitution。
2. 测试机最初没有完整 Latin Modern Sans/Math 字体；第一次 Homebrew cask 安装还遇到已有 `lmroman` 文件冲突。
3. macOS 上 uv editable install 生成的 `.pth` 带 hidden flag，导致该环境下 Python 间歇性跳过 editable path。
4. 最初的 model-evaluation parity panel 使用 `set_aspect('equal')`，导致与 residual panel 的纵向位置和高度不一致。
5. Poppler 26.08.0 对 Matplotlib 3.11.1 写出的 CFF OpenType subset 报 `Mismatch between font type and embedded font file` syntax warning，尽管字体表显示 `CID Type 0C (OT)`、embedded=yes、subset=yes、Unicode=yes。
6. 首次 lint 发现 import order、过长行和 subprocess capture 表达不统一。
7. 第一次 post-push shell 核验把循环变量命名为 zsh 特殊数组 `path`，意外覆盖了 `PATH`，导致后续 `git` 调用报 `command not found`；SHA 三方比较已在覆盖发生前成功，但该次文件树核验不计为有效结果。

## 14. Remaining limitations

1. 当前正式路线是 Tectonic 包含 Matplotlib 矢量 PDF；Tectonic 不重新 typeset 图内文字。它满足实际最终 PDF 必经 Tectonic 的要求，但不是 PGF/TeX-native text pipeline。
2. Poppler 26.08.0 仍对 Matplotlib 生成的 CFF OpenType subset 输出 font-type mismatch syntax warning。字体实际 embedded/subset、Unicode text 可提取且视觉正确；warning 尚未在上游组合中消除。
3. 第一版只验证 macOS/Apple Silicon + Homebrew 字体路径。Linux/Windows 的字体安装位置与 Tectonic/Poppler 版本尚未形成 CI matrix。
4. 当前 17 个模板是基础 grammar，不是期刊专用规范，也不覆盖高密度 rasterized scatter、地图、3D、网络图或复杂 inset。
5. 自动检查可证明结构、字体、文本和边界，但不能可靠量化所有视觉审美；最终仍要求人工打开 PDF。
