# AxiomFig Agent Skill 闭环与架构冻结报告

## 1. 结论

本轮从 `e3e926f5cea3040d14a885962578dae6c7fde411` 开始，完成 Agent Skill 协议、
benchmark specification、multi-panel operability 审计和 Skill/runtime 安装边界审计。
已通过本地完整验证与 GitHub Actions 的实现提交为
`091411e3762f6e50c74a6630b998c1fc18185fa3`。本报告由后续 report-only commit 收录，
因此不在文件内部写入无法实现的自引用 SHA。

本轮没有修改 Python runtime、Figure Intent schema、template、Gallery 或视觉合同。Public templates
保持 `55`，正式 Gallery 保持 `118` 对。Immutable `v1.0.0` tag 未移动或重建。

v1.1.0 readiness verdict 为 **READY WITH BLOCKERS**。Agent Skill 架构已冻结，但正式发布前仍需明确
multi-panel user-data scope、完成版本与 CHANGELOG 准备，并获得发布授权。当前 benchmark 只证明规范和
合同覆盖，不证明真实 LLM 路由准确率。

## 2. Agent 架构

架构所有权冻结如下：

| 层 | 所有者 | 职责 |
|---|---|---|
| Agent Skill | `SKILL.md`、`references/agent-protocol.md`、template knowledge | 自然语言理解、推荐、澄清、字段映射和执行编排 |
| Figure Intent | `references/figure-intent.md`、`intent.py` | 唯一 LLM/runtime 边界 |
| Template system | registry、family contract、adapter、builder | discovery、科学输入合同、数据归一化、plot grammar |
| Deterministic runtime | style、layout、ornaments、typography、rendering | 可确定的视觉与物理输出规则 |
| Validation | `validation.py`、tests、release Evaluation | 观察并拒绝违反合同的输入或产物 |

未新增 `agent`、`llm`、`planner`、`reasoner` 或 `router` Python package，也未增加 LLM provider、prompt
framework 或科学分析依赖。Figure Intent 仍只允许 `template`、`data`、`geometry`、`typography` 和
`semantics`。

## 3. Agent Execution Protocol

新增 `references/agent-protocol.md`，将执行路径冻结为九个门：

1. 检查请求与可用数据 schema；
2. 在最终选择 template 前解析科学意图；
3. 判断信息是否充分；
4. 选择一个 registered template；
5. 读取一个 family contract 并确认 direct/precomputed；
6. 必要时无损归一化为 CSV/JSON；
7. 构造 minimal Figure Intent；
8. 执行并验证；
9. 返回 PDF、PNG 和最小 provenance。

协议要求在 uncertainty type、precomputed ordination/Mantel/survival result、歧义字段映射或无法区分
distribution 与 summary comparison 时最小澄清。字体、line width、tick、legend、marker、bar、Colorbar、
margin 和已注册 geometry 不得向用户提问。

输入归一化属于 Skill 层。Excel、Parquet、HDF5、NPZ、RDS 等数据只有在保持值、label、missingness、unit
和 order 时，才可提取为临时 CSV/JSON；归一化不得执行统计分析或静默聚合。

## 4. SKILL 路由与 token 成本

旧路由先选 template、后在歧义时读取 recommendation knowledge。本轮调整为先检查数据和科学意图，必要时
读取一个 routed knowledge topic，再完成 template selection。

| 项目 | Baseline | Final |
|---|---:|---:|
| `SKILL.md` | `2906 bytes` | `3361 bytes` |
| Template Registry | `2895 bytes` | `2895 bytes` |
| selected scatter contract | `652 bytes` | `652 bytes` |
| representative Figure Intent | `116 bytes` file / `60 bytes` evaluation sample | unchanged |
| discovery estimate | `1629 tokens` | `1742 tokens` |

Discovery estimate 按 repository 既有 byte/4 方法计算，增加 `113 tokens`（约 `6.9%`），未翻倍。
Benchmark 和完整 Agent protocol 不属于 normal request 的默认加载集合。

## 5. Agent protocol benchmark

新增：

- `tests/evaluation/agent_protocol_cases.yaml`；
- `tests/evaluation/agent_protocol.py`；
- `tests/test_agent_protocol_benchmark.py`。

Benchmark 包含 `72` 个科研请求 specification：

| Action | Cases |
|---|---:|
| `render` | `55`，逐一覆盖全部 public templates |
| `clarify` | `6` |
| `require_precomputed` | `5` |
| `unsupported` | `6` |

覆盖 explicit/implicit template、direct/precomputed、ambiguity、column mapping、forbidden inference、
geometry、typography、invalid、composition 和 unsupported domain。Structural validator 验证：

- case ID 与 action 有效且唯一；
- template 存在；
- required roles 与 family contract 一致；
- direct/precomputed 与 `input_mode` 一致；
- 55 个 public templates 和 13 个 families 均有 render specification；
- benchmark 不包含禁止的低层视觉字段。

**Actual LLM runs performed: no.** 因此本轮没有宣称 prompt routing accuracy、clarification quality 或模型
pass rate。当前成果是可用于未来真实 Agent 运行的规范语料与确定性预检器。

## 6. Multi-panel composition 审计

**Verdict: PARTIAL。** 当前事实如下：

- `layouts/horizontal_2`、`grid_2x2`、`grid_2x3`、`grid_3x2` 可通过无数据 Figure Intent 渲染固定
  canonical composition；
- layout contract 声明 `panels`，但 layouts 没有 adapter；
- `Figure Intent.data` 只映射 scalar CSV column 或 JSON key，不接受 nested Figure Intent；
- CLI 无法将多个独立外部 dataset 组成用户指定 panel。

实测 `layouts.grid_2x2` canonical intent 生成 `5` 个 axes；带 `data.panels` 的 intent 在执行时明确失败：
`no v1 data adapter for template 'layouts/grid_2x2'`。

未来可评估 `panels: [<Figure Intent>, ...]`，但这会改变 public schema。本轮只记录设计约束，没有把它写成
已实现能力，也没有建立第二套 intent schema。

## 7. Skill 与 runtime 安装边界

**架构决定：保留双部件模型。**

- repository/Skill checkout 拥有 `SKILL.md`、references、recommendation knowledge、examples 和 Agent route；
- Python wheel 拥有 CLI、registry、contracts、adapters、builders、styles、fonts 和 LaTeX runtime resources。

wheel inspection 显示 `114` 个文件，包含所有 runtime resources 与 family contracts，不包含
`references/template-knowledge/`、evaluation corpus 或 top-level Skill 文档。`pip install axiomfig` 单独不能
提供 Agent Skill 文档；README 和 Agent protocol 已明确这一点。没有为对称性把 references 复制进 wheel，
runtime 也不依赖 repository root。

## 8. v1.1.0 readiness

**Verdict: READY WITH BLOCKERS。**

已具备：

- 冻结的 Agent/runtime ownership；
- operational Agent state machine；
- 72-case benchmark specification 与 structural validation；
- 55/55 Figure Intent runtime Evaluation；
- wheel、clean-clone 和 CLI E2E；
- Python 3.11/3.12 CI。

发布前 blockers：

1. `pyproject.toml` 和 installed distribution 仍为 `1.0.0`；
2. `CHANGELOG.md` 只有 `1.0.0`，尚无经批准的 `1.1.0` release notes；
3. README 安装命令仍正确指向 immutable `v1.0.0`，不能在未发布前声称 v1.1；
4. 如果 v1.1 scope 包含 user-data multi-panel composition，该能力仍为 PARTIAL；
5. benchmark 尚未执行真实 LLM，因此不能发布模型路由准确率声明；
6. 未获得本轮创建 tag/Release 的授权。

## 9. 视觉债务

- `ordination/pca_biplot` loading-label clearance：局部 P2，deferred；

两项问题不是 Agent 架构 blocker，也未被错误提升为全局视觉合同。
