## 3. Bar uncertainty: freeze the canonical tabular contract

### 3.1 Canonical Agent-facing schema

For point-estimate Bar grammars that support uncertainty (`bar.simple` and `bar.grouped`), add a canonical interval representation based on explicit endpoints:

```text
simple interval
category | value | lower | upper

grouped interval
category | group | value | lower | upper
```

Scientific invariants:

```text
lower <= value <= upper
```

All `value`, `lower`, and `upper` fields must be finite and must produce finite renderable derived geometry.

`uncertainty_type` remains mandatory whenever uncertainty is supplied. It is semantic metadata and must never be inferred. Examples include `SD`, `SE`, `95% CI`, `95% PI`, or an explicitly supplied credible interval description.

The canonical external representation for interval uncertainty should be endpoint columns because it maps naturally to CSV/DataFrame tables and makes asymmetric intervals explicit.

### 3.2 Backward-compatible `error`

Existing `error` input remains executable for compatibility and for the common symmetric deviation case. Do not silently remove a previously executable public input.

Rules:

- `error` and (`lower`, `upper`) are mutually exclusive;
- `lower` and `upper` must be supplied together;
- any uncertainty representation requires `uncertainty_type`;
- endpoint input is deterministically converted internally to lower/upper error widths if the Matplotlib builder requires widths;
- conversion must reject negative widths, non-finite widths, or overflow of the combined span;
- do not expose internal `(n, 2)` Matplotlib-oriented error arrays as the recommended DataFrame schema;
- existing programmatic asymmetric `error` compatibility may remain if currently tested, but the Agent guide should recommend explicit `lower`/`upper` columns for external tabular asymmetric intervals.

The adapter owns this conversion. Builders should consume normalized uncertainty data and should not independently reinterpret the scientific interval.

### 3.3 Required uncertainty regressions

Test through the real public Figure Intent boundary, not only private helpers:

- simple symmetric `error` vertical/horizontal;
- grouped symmetric `error` vertical/horizontal;
- simple `lower`/`upper` vertical/horizontal;
- grouped `lower`/`upper` vertical/horizontal;
- asymmetric intervals;
- `lower == value == upper`;
- `lower > value`;
- `upper < value`;
- missing lower only;
- missing upper only;
- mixing `error` with lower/upper;
- missing `uncertainty_type`;
- NaN/Inf in any field;
- individually finite endpoints whose span overflows;
- very small finite intervals;
- interval artists fully contained inside the plotted value-axis limits;
- no raw `KeyError`, `OverflowError`, `TypeError`, `IndexError`, `AssertionError`, or Matplotlib internal exception at the public boundary for malformed user data.

At least one canonical CSV + Figure Intent example must use `lower` and `upper` columns.

## 4. Sparse versus complete grids: grammar-specific semantics

The current adapter applies complete Cartesian-grid validation broadly. Replace the blanket rule with explicit grammar-level semantics.

### 4.1 `bar.grouped`: allow sparse combinations

For grouped bars, a missing `(category, group)` row may represent an unavailable/not-supplied measurement and should be renderable as an absent bar/gap.

Required semantics:

- duplicate `(category, group)` remains an error;
- missing combination is **absent**, never interpreted as zero;
- explicit numeric `0` is a supplied zero value and remains distinguishable from an absent row in artist geometry/tests;
- first-seen category order and first-seen global group order remain deterministic;
- bar offsets must be based on the global group order so a missing group does not cause the remaining bar to shift into another group's semantic position;
- vertical and horizontal orientation must behave equivalently;
- legends must remain deterministic and include the supplied global group set;
- sparse grouped uncertainty must work for both `error` and endpoint interval forms.

Do not densify sparse grouped data with hidden zero filling.

### 4.2 Keep complete grids where omission would be scientifically ambiguous

Retain fail-closed complete-grid behavior for grammars where a missing row would be visually indistinguishable from zero contribution or would invalidate a paired/compositional structure, unless a stronger task-local scientific argument and tests justify a different rule:

- `bar.stacked`;
- `bar.normalized_stacked`;
- `bar.grouped_stacked`;
- `bar.diverging_stacked`;
- `bar.mirrored`.

The rationale must be documented concisely in `bar.md`: for cumulative/compositional/paired grammars, omission can silently change totals or look like a zero contribution, so completeness is part of the scientific contract.

Do not weaken these completeness rules merely to make real-world ragged data render without explicit scientific meaning.

### 4.3 Sparse-grid tests

Add focused tests proving:

- grouped sparse vertical geometry;
- grouped sparse horizontal geometry;
- missing bar remains absent;
- explicit zero is represented separately from absence;
- sparse group offsets preserve semantic group slots;
- group legend/order is deterministic;
- sparse grouped interval uncertainty is contained;
- incomplete stacked/normalized/grouped-stacked/diverging/mirrored inputs still fail bounded;
- duplicate grouped logical keys still fail;
- no hidden aggregation or fill-zero path appears in adapter or builder.

## 5. Normalize the normalization semantics in documentation

There is currently a wording conflict between Bar family guidance and higher-level trend/comparison guidance.

Freeze this distinction:

### Runtime-owned plotting normalization

A registered grammar may perform a deterministic display normalization when the user explicitly selects that grammar/semantic operation and no scientific estimator is being invented. For `bar.normalized_stacked`:

```text
normalization = normalize
```

may deterministically convert valid non-negative supplied components to within-category proportions.

```text
normalization = proportion
```

means the user supplies proportions already satisfying the documented absolute tolerance.

### Upstream scientific/statistical normalization

Normalization requiring a scientific denominator, reference population, fitted model, baseline correction, batch correction, transformation choice, estimator, or domain-specific interpretation remains upstream and must not be invented by AxiomFig.

Update `references/template-knowledge/trend-comparison.md`, `families/bar.md`, and any other affected routing text so they agree exactly on this distinction. Do not duplicate executable numeric visual defaults into Markdown.
